# 南门DNS 2.9.5 测试版 · 修复证据

- 版本：`versionCode 110 / versionName 2.9.5`
- 内核：`nanmen_core 1.13.24`
- 基线：2.9.2-G3（vc107）＋流程方案第 13 节 D-G2-01
- 范围：证书状态三层修复、SSID 运行时接线、v2 小时桶迁移、内核版本可独立验证、MITM 页面可用性

## 1. D-G2-01 证书状态误报（第 13 节 L1/L2/L3）

### L1 取证权威化

文件：`app/src/main/java/com/namu/dns/RootCaManager.kt`

- `inspect` 不再把 `MitmManager.systemCertInstalled`（本进程视图）当作结论，只把它记为 `visibleInSelf`。
- 读取模块证书并与本地 CA 比较，产出 `moduleInstalled / moduleCertMatches`。
- 在同一个 su 会话里输出 namespace 块：`self`、`init:1`、`zygote:<pid>`；每块包含该 namespace 的 `/proc/<pid>/mounts`，以及 `nsenter -t <pid> -m cat <target>/<cert>` 读到的证书。
- `mountedInZygote` 只有在 zygote namespace 顶层 source 为 `STAGING_DIR` **且证书正文匹配** 时才为真。
- `moduleOnDisk = moduleInstalled && moduleCertMatches`。
- 三事实之外保留 `conflictSources`：只有 `/data/adb/modules/...`、`tmpfs` 等明确外部覆盖层才算冲突；`/dev/block/...` 系统底层挂载只表示“尚未注入”，不误报冲突。

### L2 卸载覆盖全

文件：`app/src/main/java/com/namu/dns/TrustModuleGenerator.kt`

- 新增 `cleanup-all.sh`：
  - 先清本进程（App 自身）namespace；
  - 扫描 `/proc/[0-9]*/mounts`，用 `awk` 只选 source == 本项目 staging 的进程；
  - 用 `readlink /proc/<pid>/ns/mnt` 取 namespace inode 去重；
  - 逐个 `nsenter -t <pid> -m` 执行 `--here`，只 umount 本项目 staging；
  - `umount` 失败自动 `umount -l` 兜底；
  - 输出 `__REMOVAL_CLEARED__`、`__REMOVAL_FAILED__`、`__REMOVAL_FAILED_NS__`。
- `remove.sh` 只有全部 namespace 清理成功后才删除模块/状态；失败保留现场供重试。
- 注入前更新 CA 的旧层清理也改用同一 `cleanup-all.sh`，不再只遍历 init/zygote。
- 移除成功后 `RootCaManager.remove` 立即用 `MitmManager.systemCertInstalled` 复核本进程；若仍可见且已清理 0 处，会明确提示“手动复制进系统区，请到系统凭据设置删除”，不再让用户对着打不开的路径猜。

### L3 状态合成

文件：`RootCaManager.kt`、`Models.kt`、`MitmViewModel.kt`、`MitmScreen.kt`

- `RootCaManager.resolveTrustState(caExists, snapshot, removal)` 为纯函数，枚举 9 个互斥状态：
  `NOT_GENERATED / GENERATED_NOT_INSTALLED / INSTALLED_PENDING / ACTIVE / CONFLICT / INJECT_FAILED / REMOVED / RESIDUAL / UNVERIFIABLE`。
- `ACTIVE` 只看 `mountedInZygote`；不再叠加磁盘模块状态，避免“模块删了但 zygote 仍挂载”被误判。
- `CONFLICT` 不再被 `moduleInstalled` 门控，第三方模块盖顶层仍会报。
- `AppConfig` 新增落盘字段：`caLastRemovalAt / caLastRemovalCleared / caLastRemovalFailed / caLastRemovalFailedNs`。
- `MitmViewModel.removeSystemCa` 把 `RemovalReport` 写入设置；`REMOVED` 必须同时满足三事实全否 + 有移除记录。
- `RESIDUAL` 展示失败数量，并提供“清理残留证书”行；失败才在消息里提示重启。
- `UNVERIFIABLE` 仅由无 Root 触发，状态值为“无法核验”，全流程不出现“已检测到”。

## 2. SSID 运行时接线（评审图）

文件：`AutoConnect.kt`、`SsidTrigger.kt`、`ConfigStore.kt`

- `AutoConnect.schedule/attempt` 现在消费 `SsidTrigger.active` 与 `ConfigStore.effectiveSsidTriggers`：
  - `autoConnect` 开：维持原“网络恢复即连接”；
  - `autoConnect` 关且 `ssidTriggerEnabled` 开：只有当前 SSID 命中 Profile + 模块 `[General]` 合并名单才拉起 VPN；
  - 两项都关：不再注册无意义的连接尝试。
- `SsidTrigger.state/active` 增加 `names` 参数，默认仍用 Profile 名单；运行时调用传合并名单。
- 33+ 权限已用 `requiredPermissions()` 一次性申请 `NEARBY_WIFI_DEVICES + ACCESS_FINE_LOCATION`，不会只申请 `permissionName()` 单个权限而永久停在 `needsPermission`。

## 3. v2 小时桶迁移不再受停写盘门控

文件：`core/src/hits.rs`

- `load_history` 检测 `version < 3` 后，校正完本地小时桶立即 `persist_inner()` 写回 v3。
- 这是一次性迁移，不再检查 `persist_enabled`：用户关闭摘要时运行期仍停写盘，但旧 v2 文件不会每次启动都被新时区偏移二次校正。
- 新增 `v2_local_buckets_are_upgraded_even_when_persist_disabled` 单测。

## 4. 内核产物可独立验证

文件：`core/src/lib.rs`、`core/build-android.sh`

- 新增导出静态标记 `NAMU_CORE_VERSION = b"nanmen_core-1.13.24"`。
- `build-android.sh` 打包前对两个 ABI 的 `.so` 执行 `grep -aFq "nanmen_core-$VER"`，缺失即构建失败。
- 评审可直接对 `.so` 做 `strings`/`grep`，不必只信源码或 `kernel_version.txt`；App 内 `NativeCore.nativeVersion()` 仍显示同一版本。

## 5. MITM 页面可用性（评审图）

文件：`MitmScreen.kt`、`MitmViewModel.kt`、`Actions.kt`

- 证书 PEM/DER 与模块 zip 统一导出到公共 `下载/NamuDNS`；29+ 走 MediaStore，不再只落在 `filesDir/mitm/export`。
- CA SHA-256 改为等宽分组主值、可换行，右侧独立 48dp「复制」按钮，不再塞进 13/18 辅助字号且不可点。
- 系统状态行改为单一来源 `resolveTrustState`；操作行（安装/修复、移除）只表达动作，不再重复计算“需要更新”等状态。
- 「移除系统证书」在系统区可见但模块不存在（手动安装态）也可点击；无 staging 可清时给出系统凭据设置路径。
- 安装失败态新增「导出安装日志」：`RootCaManager.diagnosticLog()` 读取固定日志/状态，`Actions.exportText` 写入公共下载目录，可直接打开或分享。
- 主副标题改为“做什么、影响谁、要不要重启”；`/data/adb/...`、staging、bind、namespace 等技术细节只留在 README/证据文档和导出日志。
- 「移除系统证书」确认弹窗同步去掉 namespace、staging、fork、APEX 等开发词；状态值改为「证书区冲突」「安装未完成」。

## 6. 验收覆盖

- Kotlin 新增：三事实到 9 状态全枚举、namespace 块解析、移除报告解析、外部覆盖层判定、PEM 换行比较。
- Rust 新增：v2→v3 在 `persist_enabled=false` 时仍写回。
- 脚本测试：`cleanup-all.sh` 通过 `sh -n`，并断言包含 `readlink`、`umount`、`__REMOVAL_FAILED_NS__`。
